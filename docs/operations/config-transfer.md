# 配置导入导出

入口：系统管理 → 配置导入导出，仅管理员可操作。适合将配置转移到另一个已初始化的平台，不替代整库及 storage 的灾难恢复备份。

## 继续使用已有平台数据库

如果仅更换部署机器，仍连接原有平台 PostgreSQL 库，不需要执行配置导入：原库中的数据源、同步任务、任务组及系统设置会直接使用，不会清空或重建。必须一并迁移原 storage 目录，特别是 `.platform/config.json`，它包含解密已有凭据所需的密钥。原密码和 Webhook 也可继续使用，无需重新配置。

迁移前停止旧平台实例，避免两个实例争用同一控制锁。持久化目录保持原权限和 UID/GID；路径仍使用原容器挂载位置。数据库版本较旧时先运行既有更新脚本迁移。不要删除原密钥文件或对已有库重新初始化；仅有数据库而没有配套密钥文件，无法解密原凭据。制品及日志等文件仍依赖原 storage／制品缓存挂载，不能只迁数据库。

下述不含密码的 JSON 配置迁移用于另一套新平台，不等同于完整部署迁移或断点恢复。

## 导出范围

- 数据源：连接类型、名称、地址、端口、数据库、用户名、TLS 配置；不包含密码。
- 同步任务：当前草稿（没有草稿时使用已应用配置）、任务组、来源与目标映射、消息格式、调优参数。自动包含所引用的数据源及任务组。
- 系统配置：运行容量、登录与会话策略、告警规则。不包含 Webhook、账号、会话、平台密钥、环境变量或元数据库连接信息。
- 制品仅保存版本及 SHA-256，不包含二进制文件或本机路径。

文件为带格式版本的 JSON。当前文件上限 512 KiB，最多包含 500 个数据源、500 个任务组及 1000 个任务；超过限制会拒绝操作，不截断配置。文件虽不包含凭据，仍含内部连接地址，应妥善保管。

无法解析的任务草稿不导出，先修正配置再重试。无效文件、未知格式版本及包含额外凭据字段的文件不会被当作有效迁移包接受。

## 导入步骤与行为

1. 在目标平台选择文件，查看预览、冲突和缺失制品提醒。此时不写入配置。
2. 数据源或任务同名时拒绝整批导入，不覆盖已有对象；可调整包中的名称后重新预览。同名任务组只作为现有文件夹复用，不修改其属性，不增加权限。
3. 确认执行后在一个事务中创建数据源、任务与分组关系，并应用所选系统设置。中途失败全部回滚；确认前目标配置发生相关变化时要求重新预览。
4. 数据源、任务使用新 ID，任务归当前导入管理员管理，不复制用户授权。数据库型数据源标记为“待配置密码”，编辑后填写真实密码；Kafka 目前不需要连接密码。
5. 已存在且校验值匹配的制品可自动绑定，否则需上传并重新选择制品。
6. 导入任务均为停止状态，不继承预检结果、运行记录、检查点、性能指标、日志和外部资源绑定。补配密码、核对制品及资源、重新预检后，由用户手动启动。

复制槽、Publication 和 Topic 名称属于任务配置，可以保留在草稿中，但不表示目标平台已经绑定或可以安全复用。平台不会在导入阶段连接业务源端、创建复制资源或 Topic。跨平台并行使用同一复制槽存在冲突，应先核对旧实例和复制资源。配置迁移不能保证从旧位点连续消费，重新全量或重建消费者可能产生重复数据。

导入系统配置会替换目标平台的容量、会话策略及告警规则。容量不能低于当前已占用量；告警先关闭，目标已有 Webhook 不覆盖，新平台须重新配置。已有登录会话的截止时间不因导入而延长。

## 部署说明

本次更新包含数据库迁移 29、30：为缺失密码的导入数据源增加显式状态，并持久化任务组排序。旧数据源默认不变，普通创建仍要求数据库连接密码。使用既有更新脚本执行备份、迁移、重启即可，不新增环境变量或挂载参数。

导入、导出以及导入产生的新配置均记录审计；审计不记录配置包正文、密码或 Webhook。
