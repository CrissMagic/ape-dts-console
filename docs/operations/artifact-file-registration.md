# 文件上传与容器文件制品登记

管理员进入「运行制品 → 登记制品」，默认从本地上传，也可切换到容器文件选择。上传目录为当前可写本地存储配置下的 `artifact-inbox`，即 `/data/storage/<relative_prefix>/artifact-inbox`；前缀为空时为 `/data/storage/artifact-inbox`。无需新增挂载，沿用 `/data/storage` 数据卷。

## 操作

1. 在「本地上传」选择 Linux ELF 二进制、`.tar.gz` 或 `.tar.xz`，等待上传和校验完成。进度达到 100% 仅表示传输完成，仍需等待服务端校验。
2. 如文件已在容器中，切换「选择容器文件」，点击「刷新文件」并选择文件。只扫描目录的直接文件，不递归扫描。
3. 查看服务端计算的可执行文件 SHA-256 和大小，核对或修改版本标识、来源。
4. 点击「登记制品」。登记后即可在任务页面选择，无需场景认证、手动校验或手动启用；包不兼容或无法执行时，在启动记录和运行日志中显示错误。

哈希是当前文件的内容指纹，不代表文件来源可信；平台不会为了识别版本执行该文件。文件名仅用于预填版本，管理员可以修改。

取消的是用户侧认证流程，不是文件安全检查。上传和登记仍检查摘要、大小、ELF 架构及压缩包安全边界；隔离制品不能用于任务，损坏或绑定不一致仍拒绝启动。历史认证记录不被修改，也不会为未认证的包伪造认证成功。

上传保留原文件名，同名文件已存在时拒绝覆盖，请更名后重试或选择已有容器文件。上传失败或中断会清理本次临时文件；成功上传的文件保留在目录中，关闭登记弹窗不会删除，可稍后从容器文件中继续登记。

## 默认本地存储

新安装及升级后的平台启动时，仅在 `storage_profiles` 完全为空时创建默认本地可写配置，目录为 `/data/storage`。配置和审计均标记为系统创建，审计动作 `DEFAULT_LOCAL_STORAGE_CREATED`；不会伪造存储测试成功。已有任意配置（包括草稿、只读、已停用配置）均不自动修改或重新启用。

此版本包含数据库迁移 19，用于区分存储配置的用户与系统来源。部署前备份数据库和数据卷，按现有升级流程执行 `security-cli upgrade --backup-confirmed`，再启动应用。升级后检查默认配置数量、来源和审计；不应出现重复默认配置。回滚旧版本需配套恢复升级前数据库备份，不要直接让旧镜像连接新模式。本轮实现不会自动升级现有测试容器。

## 压缩包与安全边界

- 压缩包必须恰好包含一个文件名为 `ape-dts`、`ape_dts` 或 `dt-main` 的 ELF 可执行文件，目录层级不限；缺失或存在多个候选时拒绝，不猜选。仅包含 `dtscli` 而没有有效引擎时，提示改选 `ape-dts` 引擎安装包。发布后的存储文件名仍统一为 `ape-dts`。
- 单个输入文件与目标二进制上限 512 MiB；总解压流上限 2 GiB；最多 10,000 个条目，解压超时 60 秒。目录扫描也限制 10,000 个条目。
- 拒绝绝对路径、上级目录穿越、符号链接、硬链接、特殊文件及重复成员；只读取目标二进制，不把其他压缩成员写入存储目录。
- xz 解码内存上限 256 MiB；Docker 镜像安装 `xz-utils`。本地运行 API 时也需要 `xz` 可执行程序。
- 预览使用私有临时快照，完成后清理；确认登记时重新读取并核对扫描信息和预览哈希。文件发生变化时需要刷新后重新选择。
- 登记后保存至同一存储配置下独立的 `artifacts/imported/<UUID>/ape-dts`，源文件后续变化不影响已登记副本。
- 登记失败且数据库确认无引用时清理本次副本；数据库结果不可确认时保留副本，避免误删已登记文件。不要自行清空 `artifacts/imported`。

## 接口

仅管理员可用：`GET /api/artifacts/files`、`POST /api/artifacts/files/upload`、`POST /api/artifacts/files/prepare`、`POST /api/artifacts/files/register`。POST 需要现有 Session 与 CSRF 校验，要求改密的账户需先完成改密。上传请求使用 `application/octet-stream`，请求头 `x-artifact-filename` 为经过 `encodeURIComponent` 编码的原文件名；响应包含容器文件信息 `file` 和已校验摘要 `prepared`，用于后续登记。上传和预览不会创建制品记录，原始登记接口保留兼容。
