# 任务分组

任务组为全平台共享的单层文件夹，每个任务最多属于一个组。“全部任务”和“未分组”为列表筛选项，不是数据库中的组。

## 页面操作

- 列表左侧可新建组并按组查看。将任务行拖到目标组即可移动，也可通过操作栏的“分组”菜单分配，触屏或键盘操作不依赖拖拽。
- 任务编辑的来源步骤可选择分组或快捷创建。新任务随草稿一起保存分组；已有任务的分组选择即时保存，界面会明确提示，不覆盖未保存的同步配置。
- 列表默认手动刷新，可勾选自动刷新并选择 5、15、30 或 60 秒间隔。手动及定时刷新会同时更新任务状态、分组和消费进度；编辑、详情、组创建确认和变更操作期间暂停列表定时读取。
- 未刷新时保留上次采集值并显示采集时间，不再将一分钟前的进度替换成“已过期”。网络刷新失败时保留已有结果并提示失败；停止任务仍不展示旧指标，新的不可用或读取失败结果不会伪装为正常值。

## 数据与权限

- 已登录用户可创建组，组名经 NFKC、首尾空白及大小写归一后全平台唯一；本期不提供重命名或删除组。
- 分组不授予任务权限。任务列表和分配操作仍检查原有 Source、Sink 数据源使用权限；共享组列表只返回组名和 ID，不返回不可见任务及数量。
- 新建任务可同时指定组，任务及成员关系在同一事务中保存。已有任务可在运行中移动，移动只更新分组关系，不更新任务版本、草稿、预检结果或运行配置，不触发引擎停启。
- 分配请求携带 `expectedGroupId`；若任务已被其他页面移动，返回 `TASK_GROUP_ASSIGNMENT_CONFLICT`，刷新后再操作，避免覆盖其他用户的分组选择。

接口：

- `GET /api/task-groups`：返回 `{ groups: [{ id, name }] }`。
- `POST /api/task-groups`：请求 `{ name }`，返回 `{ id, name }`；重名返回 HTTP 409。
- `POST /api/tasks`：可选 `groupId`，省略或为 `null` 表示未分组。
- `PATCH /api/tasks/:taskId/group`：请求 `{ groupId, expectedGroupId }`，两项均可为 `null`；返回最新任务摘要。

写操作均要求有效会话及 CSRF 校验，并记录审计。部署时由现有升级流程执行迁移 27，新增分组及成员关系表，不重写既有任务数据；原有任务均为未分组。
