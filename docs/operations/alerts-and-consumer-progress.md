# 告警与消费进度

## 告警配置

管理员在「系统管理 → 告警配置」中保存企业微信机器人 Webhook、启用开关及规则。配置默认禁用；Webhook 加密保存，页面与审计不返回原地址。留空地址保留已有凭据。测试通知只使用已保存配置，并由管理员确认发送，不启动或修改任务。

平台每 15 秒检查任务启动失败、异常退出、恢复失败，以及配置的复制槽、WAL、Kafka Offset 和时间延迟阈值。阈值异常须达到持续时长，重复通知受间隔限制；通知正常解除可单独启停。主动停止不触发槽未连接告警；“告警解除”不代表任务已恢复运行。采集失败、过期或不可用不会被解释为正常恢复。

首次快照阶段尚未进入 CDC，不触发复制槽未连接告警，也不据此解除此前告警；复制槽不存在及 WAL 保留阈值仍会检查，避免忽略快照期间的资源缺失或磁盘压力。

已运行的 PG 任务即使停止或失败，只要已应用配置和原复制槽仍绑定，后台仍按该运行使用的源配置版本采集 WAL；停止任务不会释放复制槽，也不能据此解除 WAL 阈值告警。主动停止仍不触发槽未连接告警。WAL 告警仅在新的有效读数低于阈值后解除；源配置已变更、无可信运行绑定、采集失败或过期时保留未知状态，不报告恢复。删除平台任务后不再采集，请另行核对源库中仍保留的复制槽。

任务通知发送前保存 PENDING 记录，结果保存为 SENT 或 FAILED。通知失败不改变同步任务状态，在「通知记录」查看固定错误码；网络超时后可能无法确认对端是否已经接收，因此不能保证外部通知恰好一次。任务规则只在持有运行控制权且 READY 时执行监控，持续时间、最近发送尝试和已送达状态保存在平台数据库，容器重建不会重置这些事实。

平台健康检查独立于网页请求，每 5 秒探测元数据库并触发已有恢复流程。发现元数据库或控制面不可用立即输出 ERROR 日志，并使用最近一次成功加载、加密保存在内存中的告警配置发送企业微信通知；异常仍持续时最多每 60 秒尝试一次。未配置渠道、发送失败、恢复成功均有结构化日志。平台通知结果在内存保留最多 100 条，数据库恢复后补记通知记录；进程退出会丢失尚未补写的内存记录，容器日志仍是诊断依据。企业微信 SENT 表示接口返回成功，不能证明用户已经阅读。

平台进程、容器或宿主机完全停止时无法自行发出通知，应由 Rancher/外部监控检查健康端点及容器状态。平台启动前还未加载过的 Webhook 不能用于离线发送。

平台容器需要允许访问 `https://qyapi.weixin.qq.com`，不需要新增入站端口。仅支持企业微信官方 HTTPS Webhook，禁止重定向。其他渠道沿 `AlertSender` 接口扩展，当前没有邮件或短信实现。

## 任务自动恢复

管理员在「系统管理 → 任务恢复」配置开关、最大尝试次数和基础重试间隔。默认开启，最多尝试 3 次、基础间隔 30 秒；支持 1–10 次、5–3600 秒。设置保存后在后续恢复尝试读取，已排定的计时器不即时改期。系统配置导出包含此设置，导入旧版未带该字段的配置包时保留目标平台的恢复策略。恢复配置最初引入数据库迁移 31；此次失联检测与退避修复不新增迁移。

非主动停止的任务进程异常退出、并确认原进程已停止后恢复。每次重新预检和校验外部资源连续性，保留已应用配置、复制槽、Kafka 位点和 MySQL 检查点，不重新全量。预检失败可继续等待后重试；重启成功后再次退出也消耗同一轮次数，连续健康运行 30 分钟才重置。恢复计数位于当前平台进程内，容器重建走独立的容器恢复流程。

PG CDC 另有独立于告警开关的失联检测：每 15 秒读取源端进度，只有连续至少 60 秒取得新的、有效的复制槽未连接样本，才在任务操作锁内再次直查源库。确认仍未连接、任务仍期望运行且自动恢复开关开启时，受控停止当前容器拥有句柄的子进程，并沿用异常退出恢复流程。快照阶段、复制槽不存在、读取失败、未知状态、过期读数和已更换的运行不会触发该操作。关闭自动恢复时只记录失联日志并按已有告警配置通知，不停止任务；不能确认进程已停止时不会启动第二个进程。此机制适用于已有 ape-dts 制品，不要求重打引擎包。

重试间隔为基础值，连续失败后逐次翻倍。例如基础值 30 秒时，三次尝试分别等待 30、60、120 秒；上限为基础值与 15 分钟中的较大值，最大尝试次数不变。连续性外部探测在元数据库事务外执行，只在写入核验结果时使用短事务，避免并发恢复占住池内连接后又等待同池连接。

平台元数据库已有共享 `pg.Pool`；源库普通查询使用有超时与 TCP 保活的短生命周期连接池。CDC 复制流仍由引擎独占连接，不放入普通查询池。此次修复无需新增连接池组件、数据库迁移或部署环境变量。

超过次数、关闭策略、实际启动失败或无法确认旧进程已停止时进入人工处理，避免重复启动或占用失控。已确认退出的本实例 FAILED 运行可在列表点击「恢复任务」，重新预检并分配可用容量与指标端口；原任务历史、已应用修订和源端位点保留。仍有未确认进程的任务必须先处理进程状态，不能通过确认框绕过检查。

任务退出在数据库查询前输出 `TASK_RUNTIME_PROCESS_EXITED`，包含 taskId/runId/unitId、退出码和信号；失联检测输出 `TASK_PG_REPLICATION_STALLED`、`TASK_PG_REPLICATION_DISCONNECTED`。故障状态落库后立即调用既有通知去重机制，不依赖页面访问或下一轮告警轮询；通知失败不阻断任务恢复。重试排队、尝试、失败和人工介入分别输出 `TASK_AUTO_RECOVERY_SCHEDULED`、`TASK_AUTO_RECOVERY_ATTEMPT`、`TASK_AUTO_RECOVERY_ATTEMPT_FAILED`、`TASK_AUTO_RECOVERY_MANUAL_REQUIRED`。错误分类保留安全的驱动码、超时分类和连续性包装中的原因；通知发送失败输出 `TASK_NOTIFICATION_FAILED`、`TASK_FAILURE_NOTIFICATION_FAILED` 或 `PLATFORM_NOTIFICATION_RESULT`，不输出 Webhook、密码或原始网络异常。

## 消费进度

任务列表的「同步进度」集中展示运行状态带、实际同步阶段、复制延迟及复制状态，吞吐仍在任务详情性能页中保留。状态带表示正在运行，不表示持续同步已完成 100%。采集读取实际运行的已应用配置，不使用未启动的草稿；没有可信运行绑定或源配置已经变化时返回不可用，不连接新地址冒充正在运行的源。监控接口读后台缓存，不在每个页面请求时直连数据源。

- PG：复制槽 ACTIVE 显示为“活跃”，INACTIVE 表示未连接，不能称为槽失效；MISSING 表示未找到该槽。未确认 WAL 为当前 WAL 与 `confirmed_flush_lsn` 的字节差；保留 WAL 为当前 WAL 与 `restart_lsn` 的字节差。两项均直接按槽名查询，但 WAL 是实例级日志位置差，可能包含其他数据库的日志，不能等同于该任务待同步记录数，也不能换算为秒。保留 WAL 还可受长事务影响。
- PG 复制延迟：使用已有 PostgreSQL 驱动和数据源凭据，按槽名找到 `active_pid`，通过 `pg_stat_replication.pid` 读取 `replay_lag` 并换算毫秒。它反映源库收到消费者位点确认的时间延迟，不等于 Kafka 端到端延迟。空闲、未连接、无统计反馈或缺少统计可见权限时，时间统计可能为 NULL，任务卡片显示“暂无时间统计”；首页优先显示时间延迟，未提供时间但存在 WAL 数值时改为显示“未确认 WAL”及字节单位。不得替换成 0，也不使用 `now() - reply_time` 充当延迟。无需 JDBC、新增环境变量或数据库迁移。
- Kafka：查询任务实际 consumer group 已提交 Offset 与全部分区末端 Offset 的差。Offset 间隙不一定对应实际记录条数；无提交位点、越界或位点过期显示未知，不补零。
- 端到端时间延迟：当前制品没有可信的源端进度及下游确认时间，页面隐藏该指标，支持时再展示。不使用“当前时间减最后消息时间”，避免空闲源被误判为持续延迟。PG 复制延迟使用独立字段，不自动套用端到端时间阈值告警。

页面隐藏停止任务的旧进度；失败及过期样本有独立状态。WAL 与 Offset 采用精确十进制字符串传输，避免 JavaScript 大整数精度丢失。查看这些指标需要源端只读监控权限；权限不足只显示采集失败，不自动提升权限或修改复制槽。

任务详情优先展示「当前已应用」配置及其制品；存在草稿时可切换「待应用修改」，没有草稿不再误报未绑定制品。详情外层固定在视口内，标题、链路及操作按钮保留，超长日志、配置或阶段内容在各自卡片内滚动。

## 制品删除

管理员通过「运行制品」列表操作列删除登记。当前草稿、已应用配置、未结束运行或待恢复运行引用的制品不能删除，页面列出引用任务。并发绑定和删除由数据库锁及绑定触发器保护，不能同时成功。

删除为逻辑删除：制品退出候选列表且不能再启用、绑定或用于启动；历史运行、修订、认证证据、审计及原上传文件均保留。重复删除幂等。版本标识的原有唯一性仍保留，重新登记使用新的版本标识；物理存储清理不属于此操作。

## 本次升级

新增平台数据库迁移 21（制品逻辑删除与绑定保护）及 22（告警配置、规则与通知记录）。原环境变量、挂载目录及共享容器运行方式不变，但已有数据库必须先备份并执行新镜像的 `security-cli.js upgrade --backup-confirmed`，再启动新容器。不要直接用旧镜像连接升级后的 schema，回滚须恢复成套数据库与存储备份。

测试服务器验证：先保持告警禁用，检查列表及进度；配置测试机器人后主动发送测试通知，再开启需要的规则。不要为验证告警删除业务复制槽，使用独立测试任务和源库。
