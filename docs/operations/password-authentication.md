# 密码登录与管理员恢复

## 登录与日常操作

新环境首次启动自动创建 `admin`，仅在数据库初始化提交成功后输出一次随机临时密码（日志事件 `bootstrap.administrator_created`）。首次登录和容器命令重置后必须先修改密码，后端同时拒绝业务接口，不只是隐藏页面。日常登录只需要账号、密码；会话有效时不再要求重复输入密码，过期后重新登录。

修改密码会撤销旧会话并签发新会话。原有角色权限、账号停用、邀请激活、登录限流、CSRF 和审计继续生效。管理员操作台仍可为普通账号签发重置激活码。

日志中的临时密码是有效凭据，请限制容器日志的访问权限，及时完成首次改密。正常重启不会重新生成或打印密码。

## 登录与会话设置

管理员可在“系统管理 → 登录与会话”配置以下策略，无需新增环境变量或重启容器：

- 空闲超时：默认 480 分钟（8 小时），可设为 15 分钟至 7 天。
- 最长登录时长：默认 168 小时（7 天），可设为 1 小时至 30 天；不能短于空闲超时。

有效的认证接口请求会刷新空闲期限，页面自动刷新产生的请求也算活动；仅在表单中输入不算接口活动。最长登录时长从登录时起计算，不随活动延长。修改配置只对之后新建的登录会话生效，已有会话继续使用建立时的策略与绝对到期时间。修改密码、停用账号和撤销会话仍立即生效；修改密码签发的新会话采用当前策略。

本次数据库迁移为 `000028_session_settings.sql`。升级保留原会话的截止时间和原有 30 分钟空闲续期窗口，不延长或复活旧会话。升级后需要退出并重新登录，才能采用新默认策略。策略修改要求管理员权限、CSRF 和配置版本一致，并记录审计；并发修改冲突时需重新加载后保存。

## 部署配置

当前采用受控公司内网 HTTP 访问，支持直接通过 `http://服务器IP:映射端口/` 登录，无需隧道或额外的 Cookie 环境变量。会话 Cookie 不带 Secure，保留 HttpOnly、SameSite=Strict、`Path=/api` 和有效期；登录、改密后签发会话及退出清除会话使用相同策略，CSRF、角色权限及登录限流不变。

HTTP 不提供传输加密，账号密码和会话可能被有能力监听内网链路的人员读取。须将端口限制在可信内网访问，不得直接暴露公网；当前不增加 HTTPS 配置项，后续按需要再实现。

首次启动通过 `SCS_PLATFORM_DATABASE_CONFIG` 提供 JSON 格式的 PostgreSQL 连接配置：

```json
{"host":"postgresql-12","port":5432,"database":"your_database","username":"your_owner","password":"replace-with-real-password","tls":{"mode":"DISABLE"}}
```

生产环境按实际要求配置 TLS，JSON 支持原有 `REQUIRE` / `VERIFY_FULL` 选项。通过受限权限的 Docker env 文件传入，不把真实密码写入 Git 或命令历史。原有 `SECURITY_ARGON2_*` 四项参数仍须完整配置。

平台将连接配置与随机数据加密密钥存入 `/data/storage/.platform/config.json`；`SCS_PLATFORM_CONFIG_PATH` 可覆盖路径。必须持久化该文件所在卷。Linux 下目录权限为 `0700`，文件权限为 `0600`，文件只能由应用运行身份及受信任的部署管理员读取。平台不会覆盖已有或损坏的密钥文件。

后续启动从该文件连接数据库、读取密钥并恢复平台，无需网页输入初始化码、解锁口令或动态验证码。部署环境变量不覆盖已持久化的配置。

**数据库和配置文件必须配套备份。丢失唯一密钥文件可能导致已有数据源凭据无法解密。** 备份还应包含原有存储及运行制品卷。

## 忘记管理员密码

在已迁移且正常运行的容器内执行：

```powershell
docker exec <平台容器名> node dist/auth/reset-admin-cli.js
```

命令仅重置固定 `admin` 管理员，输出新的随机临时密码，撤销该账号的会话、未使用的激活凭据并清除该账号的登录限流状态。其他账号不受影响。下一次登录必须改密。重置产生 `DEPLOYMENT_ADMIN` 来源的审计记录，不记录临时密码。

`--help` 只显示帮助；未知参数拒绝执行。没有公开的免登录 Web 重置接口。拥有容器执行权限就拥有管理员恢复能力。

## 旧环境迁移

1. 备份数据库、存储卷，以及原有解锁材料。
2. 停止旧平台容器，保留数据库运行；不得同时运行两个控制实例。
3. 用新镜像启动一次性维护容器，挂载原持久化存储卷，连接相同 Docker 网络，并提供原数据库连接配置及 Argon2 参数。
4. 将原解锁口令通过标准输入传入以下命令，不使用命令行参数或环境变量传口令：

```text
node dist/bootstrap/security-cli.js migrate-security --backup-confirmed --administrator preview-admin
```

维护容器须启用标准输入（Docker `-i`）；输入口令后结束标准输入。不要使用会回显口令的交互终端。调用方应使用隐藏输入或受限秘密文件提供标准输入，不把口令写入脚本。

迁移保存原 DEK，不重新加密或删除任务、数据源。错误口令不会发布密钥文件。迁移后启动新容器即可自动恢复。如果文件已成功保存但数据库升级失败，保留文件并在修复数据库原因后执行：

```text
node dist/bootstrap/security-cli.js upgrade --backup-confirmed
```

`--administrator` 指定需要保留身份的原管理员。当前测试环境使用 `preview-admin`，迁移后用户名变为 `admin`，用户 ID、密码、任务归属和历史审计不变，旧登录会话失效。已经存在合法固定 `admin` 的环境可省略该参数；名称冲突或原账号不是管理员时拒绝迁移，不抢占其他账号。升级命令也支持同一参数，以便明确完成旧身份映射。

固定 `admin` 不能降级，其他角色操作保持原规则。迁移和密码恢复是不同操作，不会在每次升级时重置已有密码。

## 异常与恢复

- `DATABASE_CONFIGURATION_REQUIRED`：尚无持久配置，部署未提供数据库连接。
- `LEGACY_SECURITY_MIGRATION_REQUIRED`：检测到旧数据库，尚未保存本地密钥，需要执行一次迁移。
- `DATABASE_UPGRADE_REQUIRED`：核对数据库版本并备份后升级；高于程序版本或结构异常的数据库不能强制迁移。
- `LOCAL_STARTUP_FAILED`：检查数据库连接、配置文件完整性、权限和配套备份；平台不会重新生成密钥来掩盖错误。

如果首次初始化在写入配置文件之后、数据库事务提交之前中断，文件会被保留，以免提交结果未知时误删唯一密钥。此时请停止平台，由部署管理员核对数据库：

1. 如果平台 schema 已存在，保留配置文件，修复启动问题后重启；不得移走密钥。
2. 只有确认目标数据库没有平台 schema、没有已初始化的业务数据，且初始化事务已经结束，才能先备份并移走残留配置文件，再重新执行首次初始化。
3. 无法判断事务是否提交时，不删除、不覆盖文件，优先保留数据库及文件备份进行核对。

此恢复路径属于部署端操作，不对未登录用户开放。
