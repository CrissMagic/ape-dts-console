# PG 复制资源准备

管理员在任务编辑的 Source 步骤保存草稿后，可显式准备资源；操作使用当前有效登录会话和 CSRF 校验，无需再次输入密码，并确认新 Slot 起始位置及 WAL 保留风险。准备成功会刷新任务并重新预检，不自动启动。

- 自行管理：只核验并绑定指定的已有 Slot、Publication。
- 平台管理：首次准备只创建缺失对象，已有对象必须兼容；停止后加表只向原 Publication 追加缺失表，不覆盖旧表或重建 Slot。
- 引擎管理：本入口不执行，不能以平台登记冒充引擎准备完成。

入口 `POST /api/tasks/:taskId/pg-resources/prepare` 接收当前草稿 ID、任务版本、草稿版本及 `acknowledgeReplicationRisk: true`。首次准备要求停止且没有历史运行、应用版本或连续性基线；旧任务只允许已确认的增量加表，不能借此重建复制槽。

## 已有任务增加来源表

1. 停止任务后编辑，保留原连接、Slot、Publication、资源模式及旧表的 Topic 映射。
2. 保存时，只有相对当前已应用配置确实新增来源表，才显示二次确认。取消不会保存或修改外部资源；普通参数调整及首次创建不显示此确认。
3. 确认后保存为仅增量草稿。新增表不扫描存量，全部表从原槽已确认位点继续；若有 WAL 积压，新表可能收到添加前尚未消费的变更。原配置启用快照且无法证明已完成时，不允许通过加表放弃旧表存量。
4. 准备复制资源：平台管理追加原 Publication，自行管理只核验，需先自行将新表加入原 Publication。两种模式均要求原槽、原发布及绑定仍有效。
5. 重新预检并启动。任务 ID、历史和原槽保留；预检不切换旧连续性基线，新运行成功后才应用新配置和基线。保存或准备资源不会自动启动。

保存请求 `PATCH /api/tasks/:taskId/draft` 在新增表时要求 `acknowledgePgTableAddition: true`，服务端重新计算差异并将确认绑定保存后的草稿 ID、草稿版本和当前已应用配置。再次修改需要重新确认，不能复用其他任务或旧版本的确认。

源库应开启 `wal_level=logical`，账号需具备实际读取身份、创建发布及逻辑槽所需权限。已有 Slot 必须属于当前数据库、使用 pgoutput、未被占用；Publication 必须包含目标表并支持所需 DML。源表复制标识必须支持 UPDATE/DELETE。预检再次只读核验实际对象和绑定，不能只凭平台记录放行。

源库和平台库可位于同一 PG 实例。外部创建期间不持有平台写事务，避免逻辑槽创建等待自身 XID；通过会话锁串行准备，创建前后均核对当前版本和权限。

若外部创建成功而后续操作失败，接口返回 `PG_RESOURCE_PREPARATION_FAILED` 和 `details.created`，对象保留，禁止自动删除。先核实实际对象再重试。`platform_created=false` 不能解释为“已证明由用户创建”：先前失败且未持久化的创建证明不会在重试时凭名称推断；当前无清理授权逻辑依赖该字段。

PostgreSQL 12 的 Slot 没有可用的创建实例 UUID，平台身份为集群、数据库和 Slot 名组合；不能据此声称能识别同名删除重建的所有情况。已有运行的连续性基线与恢复检查仍需保留，不得通过首次准备入口绕过。

创建 Slot 可能持续保留 WAL；该操作不替代容器总体资源、并发容量预算、日志保留和运行环境检查。当前不要求 cgroup v2 委派，部署边界见 [容量包络](./capacity-envelope.md)。独立测试环境的结果也不代表业务环境已具备启动条件。
