# 多来源与多目标映射

## 配置范围

一个任务固定一个来源连接、一个目标 Kafka 连接。在任务编辑页“目标 Sink”的映射表中添加来源：

- PostgreSQL：每行指定 Schema 和表。
- Kafka：每行指定一个来源 Topic。
- 每行可选择或手工输入多个目标 Topic，消息向该行的全部目标分发。
- 允许不同来源共用目标 Topic；同一目标的创建策略须一致。
- 同一来源不得重复；同一行不得重复目标。Kafka 同集群内，目标不能是任务中的任一来源 Topic，以防循环转发。

目标 Topic 元数据不可获取时仍可手工填写，权限或连接错误不会被视为正常空结果。需要自动创建的 Topic 可分别设置分区数、副本数；已有 Topic 不修改。首次启动准备失败时，请刷新元数据核对已完成结果，再重新预检。Kafka 外部创建不随平台数据库事务回滚，不能假定失败时全部 Topic 都未创建。

## 运行和资源

PostgreSQL 多表共用一个复制槽和一个 Publication，运行容量仍为一个单元。准备资源会先验证全部表，已有 Publication 必须已覆盖全部所选表；平台不会擅自修改已有 Publication。增添表后需要核对发布覆盖范围，再预检、运行。

PostgreSQL 来源表支持单列主键和联合主键。预检逐表检查真实主键及全部主键列的非空条件；无主键、未取得字段元数据的表仍不能启动。完整主键列记录在预检结果中，运行时由 ape-dts 读取真实元数据，不将联合主键简化为第一列。无需为此修改源表或重建复制槽；升级后重新运行预检即可。实际消息键和 CloudCanal `pks` 由所选制品生成，仍需使用支持联合主键的制品。

Kafka 按全部来源 Topic 的实际分区数之和计算运行容量。例如两个来源各有两个分区，即四个运行单元；每行选择几个目标都不会增加来源消费者数量。任务 Group ID 继续由平台固定生成，停止和恢复保留同一 Group 的消费位置。

多目标分发使用 ape-dts 的 `topic_fanout_map`，目标用 `|` 分隔，各来源映射用逗号分隔。PG 多表同时写入过滤配置；Kafka 每个运行单元只读取对应来源和分区，避免将全部来源重复消费。需要使用支持该配置的 ape-dts 制品；不支持时会在运行阶段报错。

多目标写入不承诺跨 Topic 事务原子性。部分目标已写入而后续目标失败时，重试可能使已成功目标出现重复消息；消费端应按业务键或事件标识处理幂等。

## 兼容与监控

旧 `schemaVersion: 1` 一对一配置继续可读取和运行，编辑页显示为一行。保存后使用 `schemaVersion: 2` 的完整 `mappings` 数组；不以第一行代替完整配置。目标连接和消息格式等共有选项仍在任务层设置。

连续性证据覆盖所有来源、目标 Topic 与来源分区，映射行顺序调整不会被当作身份变化；已知 Topic ID 暂时不可见时不会清除历史身份。Kafka 2.1 等不提供 Topic ID 的 Broker 继续依赖集群与分区证据，无法可靠识别同名 Topic 删除后重建。资源集合变化、扩分区等仍按既有连续性流程处理，不能绕过失败预检直接启动。

Kafka 列表及详情的消费积压是全部来源 Topic 的 Offset Lag 合计，不乘目标数；任一来源读取失败或位置未知时，不显示部分成功值为正常零积压。PG 仍展示共享复制槽的延迟和 WAL 状态。

## 消息结构示例

“目标 Sink → 消息编码”随消息格式、JSON 模板及 Avro 字段定义开关展示格式化示例；“确认与预检”同步展示预计消息结构。多来源可切换映射查看，示例标明该行的全部目标 Topic，同一消息向这些目标分发。Kafka Raw 展示原样转发示例，不添加 CDC 包装。

示例使用固定文本字段 `id`、`name` 和假设的文本主键，不查询真实业务数据，也不写入 Kafka。库名、Schema、表名和 Topic 来自当前编辑配置；未配置时使用演示名称。标准 JSON 使用 `operation / before / after`，CloudCanal 使用 `action / before / data`。Avro 展示的是解码后的逻辑结构，不是实际二进制字节或 Avro JSON 编码。

实际字段、主键、类型元数据和 `before` 完整度仍取决于源表、PostgreSQL Replica Identity 及所选运行制品。消息中的时间戳保留制品格式，不按页面显示格式转换。查看或切换映射示例不会保存任务、执行预检或触发同步。

## 编辑布局

任务编辑仍分为来源、目标、运行配置、确认与预检四步。桌面视口下固定步骤栏和底部操作区：来源与复制资源并排；目标连接与编码选项横向排列，映射表与消息示例并排；运行制品与运行参数并排。常规配置无需整页滚动，多行映射、JSON 长内容和预检结果在内容区域内滚动。较窄窗口改为纵向布局，极短窗口保留页面滚动，确保全部控件可访问。

系统管理采用“平台信息、运行容量、告警通知”分组导航。容量和告警配置存在未保存修改时，切换分组、切换菜单、修改密码或退出登录均先确认是否放弃修改；初始容量读取尚未完成时不阻止离开。布局调整不改变任务配置格式、预检和启动流程，不增加迁移、环境变量或服务。

## 升级

此功能包含数据库迁移 23。部署前备份平台数据库和配套配置、密钥，按现有更新脚本停止旧实例并执行迁移，不需要额外环境变量或新服务。迁移保留历史单值配置，新增映射及完整 Topic 证据列。

升级后不能仅切回旧镜像：旧版本不能理解 v2 配置及新版迁移账本。需要回滚时，应恢复升级前成套备份；不要手工把多映射截成第一行。
