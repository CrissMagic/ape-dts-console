# 运行监控

## 展示与含义

任务列表与任务详情展示记录吞吐、字节吞吐、活跃单元累计写入量、队列记录数和队列字节数。趋势支持 1 小时、24 小时和 7 天窗口。

- 每 15 秒采集平台拥有的运行进程的 loopback `/metrics`，并核验监听 socket 归属。
- 吞吐使用同一进程相邻累计值的差分计算；首点、采集失败后首点及计数重置时显示“—”。
- 累计值属于当前活跃单元，阶段切换可能变化，不是整个任务的历史总量。
- 同步延迟暂不支持。APE 时间戳不作为延迟依据。
- 空值和缺口不补零、不连线。多个活跃单元中任一单元缺少某指标时，该汇总字段为空。

状态包括实时、部分缺失、已过期、暂无数据和未运行。45 秒未获得有效新样本后不再标为实时；监控读取失败不阻断任务操作，也不停止同步任务。

任务详情使用 ECharts 展示趋势，支持横向平移、底部缩放与最近采样点吸附，不再额外展示随选点移动的蓝色滑块。选择历史点后，顶部计数器联动显示该时刻的值；缺测点显示“—”，不会回退到最新值。聚焦图表后可用左右方向键逐点选择，Home / End 跳至首末采样，点击“回到最新数据”恢复跟随该次运行的最新采样。监控面板与日志刷新隔离，选点不重复渲染趋势筛选控件；数值格式化复用实例，相同数值不启动动画。

停止任务后打开性能页，默认查询近 7 天；已有采样会标注“历史性能（非实时）”及采集时间，没有采样则不显示空指标卡片。通过“性能所属运行”可选择历史运行，容器或任务重启不会把不同运行的累计量拼接。任务列表仍不显示停止任务的实时吞吐。

当前草稿配置与本次运行摘要分别展示，避免把修改后的草稿误称为运行事实。左侧为“任务配置／本次运行／阶段进度”，右侧为“运行监控／运行日志”，刷新、自动刷新与停止操作位于右侧。阶段进度保留总量未知、运行单元失败及日志恢复状态。详情首次打开聚焦标题，说明图标不自动展开，长内容在卡片内部滚动。

## 运行日志

- “日志所属运行”默认指向当前／最近一次运行，可选择未清理的历史运行；列表只在进入日志页或刷新时读取，不受指标 7 天窗口限制。运行监控和日志均标识当前／历史运行。选择历史日志时停止实时轮询，筛选和下载均作用于选中的运行；切回当前运行后恢复实时查看。切换运行重置旧筛选条件，不改变当前任务、运行摘要及停止操作的对象。平台恢复产生新运行时，已选中的历史日志保持不变。
- 进入“运行日志”页签后才开始读取，默认实时，每次请求完成后间隔 2 秒读取最新匹配记录，最多显示 500 条，按时间正序展示。单次页面查询最多扫描 8 MiB 或 64 个日志分段对象（含长行级别上下文回溯）；达到扫描上限会明确标为不完整结果，不误报“暂无日志”，可缩小时间范围或下载完整记录。切换至“运行监控”或关闭详情后停止读取；不与运行监控的自动刷新开关联动。
- 支持 ERROR、WARN、INFO 精确级别筛选，以及输出流、运行单元和时间范围。级别根据逻辑日志行开头识别，支持引擎时间戳及 ANSI 颜色，长行分片沿用首片段级别；不把 STDERR 推断成 ERROR。未识别级别的行在“全部级别”中查看，日志缺口始终保留，不能用级别过滤掩盖存储损失；首片段已丢失而无法确定后续分片级别时，明确报告 `LOG_LEVEL_CONTEXT_UNAVAILABLE` 缺口，原始分片仍可在“全部级别”查看或下载。
- 点击“筛选日志”应用条件。填写结束时间后转为历史查询；重新勾选“实时日志”清除结束时间并恢复最新窗口。取消勾选时保留当前结果，不继续定时读取。下载采用表单所选筛选条件，不受页面 500 条上限限制。
- 实时模式自动滚动到底部，向上滚动后暂停跟随，滚动回底部后继续。网络失败保留最后一次结果并提示；不使用伪造日志填补缺口。
- 实时读取在核验任务、运行及数据源权限之后，仅刷新该运行的完整已脱敏日志行，不关闭子进程、不改变日志保留策略。未完成的行、尚未完整的敏感内容继续留在安全缓冲中。浏览器每次读取的结果有上限，但历史数据仍按平台日志保留策略保存。

`GET /api/tasks/:taskId/runtime/:runId/logs` 新增可选 `order=DESC`，按最新记录选取后仍以时间正序返回；省略时保留原历史正序读取行为。读取和下载均支持可选 `level=ERROR|WARN|INFO`，原有权限、流和时间边界规则不变。无需数据库迁移或新增启动参数。

`GET /api/tasks/:taskId/runtime/runs` 返回该任务尚未清理的运行 ID、状态及开始／结束时间，按开始时间倒序；沿用当前运行读取的任务及两侧数据源权限，不返回其他任务的运行。日志保留期不变；已超期清理的日志不能通过选择历史运行恢复。

## 存储与维护

部署需包含数据库迁移 `000020_runtime_performance.sql`。仅使用平台元数据库，不修改业务 PostgreSQL 表、复制槽、Publication 或 Kafka Topic。

所有指标采样、聚合和缺口记录最长保留 7 天。维护只清理新指标表中超期数据和所属分区，不删除任务、运行或运行单元。

指标持久化在外部平台 PostgreSQL 元数据库，停止任务不会删除；容器重建后连接同一元数据库即可查询。无法补回此前未采集或已经超过保留期限的数据。24 小时与 7 天窗口使用分钟聚合，最新未完成的分钟需等待维护完成；不完整桶仍按缺口展示，不伪造连续数据。

失败重扫只重算仍有完整源数据的桶，避免保留边界的残留数据覆盖完整聚合。未完整的时间桶和采样抖动可能保守显示缺口。数据库不可写期间缺口暂存在内存；恢复前平台重启会丢失尚未持久化的缺口事件，但查询仍将缺少的时间桶显示为空，不补造采样值。

## 接口

- `POST /api/tasks/performance/query`：最多 100 个 taskIds，需会话和 CSRF；仅返回用户可见的任务。
- `GET /api/tasks/:taskId/performance?window=1h`：读取详情和趋势，不可见任务返回 404。
- 可选 `runId` 参数读取该任务的历史运行，返回 `runs` 提供近 7 天内结束及尚未结束的运行记录；不属于该任务或已超期的运行返回 404。

权限沿任务两侧数据源授权校验；不将不可见任务信息带入批量响应。
